# Flowrly

Tauri 2 + React 19 desktop app (macOS only). Time tracking for freelancers, invoicing via Fakturoid, focused-window activity tracking summarised by an LLM. Domain vocabulary lives in `CONTEXT.md`; read it before naming things.

## Commands

```sh
pnpm tauri dev            # run app (regenerates src/bindings.ts on start)
pnpm exec tsc --noEmit    # type-check frontend
pnpm exec vite build      # bundle frontend
cd src-tauri && cargo test   # Rust unit tests; also re-exports src/bindings.ts
```

## Layout

- `src-tauri/src/` Rust owns all data and logic. `commands.rs` is the only Tauri surface; `repo.rs` SQL; `activity.rs` sample aggregation; `ai.rs` rig-based extraction; `fakturoid.rs` API client; `invoice.rs` pure invoice math; `backup.rs` VACUUM INTO snapshots; `tracker.rs` polling thread.
- `src/bindings.ts` is generated by tauri-specta. Never edit by hand.
- `src/routes/*` one file per screen; `src/components/entry-form.tsx` shared create/edit form; `src/lib/api.ts` TanStack Query hooks; `src/styles/globals.css` design tokens.

## Gotchas

- `tauri-specta` / `specta` must stay on the `2.0.0-rc.*` line (pinned with `=`); the `1.x` "stable" releases target Tauri 1 and break dependency resolution.
- `rusqlite_migration` is pinned `~2.5` because 2.6 needs rustc 1.95; keep `rusqlite` on the version it requires (0.39).
- specta-typescript forbids `i64`; models use `i32`. `f64` exports as `number | null`, so the frontend does `?? 0`.
- Settings are stored as one JSON blob; new fields need a default in `Settings::default()` and are merged over defaults on load.
- Window titles of other apps require macOS Screen Recording permission; without it the tracker only sees app names.
- Fakturoid has no "invoice from generator" endpoint in v3; we copy generator fields client-side (`invoice.rs`).
- Theme follows the OS only (`prefers-color-scheme`); there is no theme switcher and no i18n.
